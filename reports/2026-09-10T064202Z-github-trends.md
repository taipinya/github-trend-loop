# GitHub 趋势项目观察 - 2026-09-10

## 本次结论

本期 Top 3 呈现出非常一致的信号：**"Agent Skill + 可视化/渲染"正在成为一条独立的工程赛道**。三个项目中有两个（archify、diagram-design）都在解决同一个问题——让编码 Agent 把代码库或系统描述转成可读、可验证、可导出的图表；而第三个（deepseek-harness）则是这条链路的底座，提供"一切皆插件"的 Agent 运行时。换句话说，前两个是"Agent 的产出物层"，第三个是"Agent 的运行时层"，三者放在一起看，能拼出一幅完整的图景：Agent 不再只是写代码，它开始承担"系统表达"和"架构沟通"的工作。

从数据上看，三个项目的 delta_stars 都相当可观（5090 / 4211 / 3519），说明这不是单个项目的偶然爆发，而是同一时间窗口内多个相关方向同时被关注。archify 和 diagram-design 的 topic 高度重叠（agent-skills、diagrams、mermaid-alternative 等），deepseek-harness 的 topic 则更偏底层（ai-agents、cordis、dsh-plugin）。这种"上层应用 + 底层运行时"同时上榜的结构，值得作为课程设计或个人项目的选题参考。

## 报告重点

- **archify**：Node.js 渲染 + 校验系统，把代码库/系统描述转成交互式系统图，强调"可验证"和"自包含 HTML"。
- **diagram-design**：38 种编辑级图表类型，纯 HTML + SVG，明确反对"Mermaid slop"，走的是设计感路线。
- **deepseek-harness**：DeepSeek 开源的 Agent harness，基于 Cordis 的"一切皆插件"架构，目前处于 developer preview。

三个项目都是 MIT 许可，但成熟度差异明显：archify 和 diagram-design 更接近"可直接用的工具"，deepseek-harness 明确标注了兼容性破坏风险。

### 1. tt-a1i/archify

#### 项目简介

archify 属于**代码可视化 / 架构即代码（architecture-as-code）**领域。从 README 和 topic 看，它是一个 Node.js 的渲染与校验系统，面向 Cursor、Claude Code、Codex CLI、OpenCode 等编码 Agent，把"代码库或系统描述"转换成"精致的、可交互的系统地图"，并且以自包含 HTML 的形式输出，带运动和清晰导出能力。

技术原理上，它可能采用了"Agent 生成中间描述 → Node.js 渲染器校验并渲染 → 输出自包含 HTML"的流水线。topic 里同时出现了 `architecture-as-code`、`diagram-as-code`、`text-to-diagram`、`mermaid-alternative`，说明它想替代传统文本转图工具（如 Mermaid）在架构图场景下的表达力不足问题。`dsh-plugin` 和 `deepseek-harness` 这两个 topic 暗示它可能与 DeepSeek Harness 有插件级集成。

它完成的任务是：让 Agent 在对话中直接产出可交付的架构图、工作流图、时序图、数据流图和生命周期图，而不是让用户手动去画。

它完成的任务是：为 Agent 提供一个可扩展的运行时底座，让开发者通过插件方式添加能力，而不是修改核心代码。archify 的 topic 里出现 `dsh-plugin` 和 `deepseek-harness`，暗示 archify 可能是 dsh 生态的一个插件。

- **机器人仓储调度**：把路径规划、库存查询、任务分配做成插件，通过 dsh 的插件模型统一管理不同厂商的能力模块。
- **教学用 Agent 框架**：在课程中让学生实现一个插件（如天气查询），理解 Agent 运行时的插件加载、生命周期和上下文传递。

#### 风险或局限

- **生产成熟度**：README 明确标注 developer preview，且警告会有兼容性破坏性变更，不适合直接用于生产环境。
- **信息不足**：README 摘要没有展开具体 API 和插件接口，需要进一步读文档站点和源码才能评估。
- **维护风险**：open_issues 为 0，无法从 issue 量判断社区活跃度和问题处理能力；需要观察后续 issue 开放情况。
- **依赖成本**：依赖 Cordis 生态，如果 Cordis 本身迭代快，dsh 的稳定性会受影响；TypeScript 栈也意味着团队需要相应技术储备。
- **工程复杂度**：插件化架构虽然灵活，但调试跨插件问题时链路较长，对开发者要求较高。
- **许可证**：MIT，商用友好，但 developer preview 阶段的功能承诺需谨慎对待。
